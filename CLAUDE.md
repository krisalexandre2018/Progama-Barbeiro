### Application Flow

1. **LoadingScreen** - First screen shown
   - Initializes Firebase via `Firebase.initializeApp()`
   - On success → navigates to HomeScreen
   - On failure → navigates to ErrorScreen

2. **HomeScreen** - Main menu
   - Two main paths: Admin access or Client area

3. **Admin Path**:
   - LoginAdminScreen → AdminPanelScreen (create time slots) → AdminAgendaScreen (view all bookings)

4. **Client Path**:
   - LoginClientScreen → ClientPanelScreen (view/book available slots) → MyAppointmentsScreen (manage bookings)
   - Alternative: RegisterClientScreen (registration) or ForgotPasswordScreen → ResetPasswordScreen (password recovery)

### Firebase Data Structure

**Collections:**

1. `usuarios` (Users)
   - Document ID: SHA-256 hash of CPF
   - Fields: `nome`, `senha` (bcrypt hash), `cpf_ultimos_digitos`, `data_criacao`, `agendamentos_ativos`

2. `agendamentos` (Appointments)
   - Document ID: `{YYYY-MM-DD}_{HHMM}` (e.g., "2025-10-25_1430")
   - Fields: `data` (BR format), `data_iso` (YYYY-MM-DD), `dia_semana`, `hora`, `status` ('livre'/'agendado'), `cliente_cpf` (hashed), `cliente_nome`

3. `recuperacao_senha` (Password Recovery)
   - Document ID: SHA-256 hash of CPF
   - Fields: `codigo` (6-digit), `usado` (boolean), `criado_em`

### Security Model

- **CPF Storage**: Never stored in plaintext - always SHA-256 hashed
- **Passwords**: Hashed using bcrypt with automatic salt generation
- **Admin Credentials**: Stored in environment variables (`ADMIN_CPF`, `ADMIN_SENHA`) - plain comparison (not production-ready)
- **Firebase Credentials**: Loaded from `firebase-credentials.json` (excluded from git, included in Android build)

### Key Design Patterns

**Singleton Pattern**: `FirebaseManager` uses singleton to ensure only one Firebase connection exists throughout the app lifecycle.

**Screen Manager**: All screens inherit from `MDScreen` and are managed by `MDScreenManager` for navigation.

**Business Rules**:
- Clients can only have 1 active appointment at a time (enforced in `agendar_horario()`)
- Time slots are generated in 30-minute intervals from 7:00 to 23:30
- Appointments are only shown for current day forward (`data_iso >= hoje`)

### State Management

**Client Context**: When a client logs in, their CPF and name are stored in `ClientePainel`:
- `cliente_painel.cpf_cliente`
- `cliente_painel.nome_cliente`

These are accessed by `MeusAgendamentos` via `self.manager.get_screen('cliente_painel')`.
